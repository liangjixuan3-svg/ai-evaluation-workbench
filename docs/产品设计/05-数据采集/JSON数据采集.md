# JSON 数据采集

## 1. 模块目标

把来源和字段结构不固定的客服对话 JSON 转换成工作台统一数据结构，为后续抽样、评测、归因和复测提供可靠数据。首版面向人工上传，单个文件不超过 20 MB，单批不超过 10,000 条对话。

## 2. 页面入口

左侧导航“05 数据采集”，路由为 `/runs/import`。

数据采集只负责识别、校验和入库，不调用评测模型。确认入库后，用户继续进入“06 发起评测”。

## 3. 操作流程

### 3.1 上传 JSON

- 接受 UTF-8 JSON 文件。
- 支持根节点为数组，也支持记录数组位于对象内部，例如 `payload.conversations`。
- 上传后只创建临时导入会话，不立即写入正式对话表。
- 系统返回候选记录数组、记录数、字段建议和原始样本。

### 3.2 确认字段映射

标准化对话包含以下字段：

- 对话 ID：优先映射业务 ID；缺失时可根据原始记录生成稳定哈希。
- 发生时间：支持 ISO-8601 和常见时间戳。
- 场景：可选，例如退款进度查询、物流异常催单。
- 会话状态：可选。
- 消息：必填。

消息支持两种结构：

1. 消息数组：映射消息数组、角色字段和内容字段。
2. 问答字段：分别映射用户问题和 AI 回答，系统转换成两条消息。

系统使用字段名称和样本值在本地生成映射建议，不使用大模型自动决定字段。未映射字段仍保存在原始正文中。

### 3.3 生成脱敏预览

确认入库前展示：

- 原始记录与标准化对话的对照。
- 时间、场景、状态和消息解析结果。
- 手机号、订单号等敏感信息的脱敏结果。
- 缺失必填字段、重复 ID 和无法解析记录的数量。

默认情况下，只要存在错误记录就阻止整批入库；用户也可以明确选择跳过错误记录。

### 3.4 确认入库

- 每次确认创建一个数据源和一个采集批次。
- 数据源 ID 与外部对话 ID 组成幂等键，重复导入不会覆盖已有对话。
- 页面显示新增数、跳过数、错误数、批次 ID 和可评测数量。
- 审计记录保存文件名、文件哈希、字段映射和操作时间，不保存模型 API Key。

## 4. 异常与安全

- 非 JSON、文件过大、找不到记录数组或必填映射不完整时，不创建正式数据。
- 文件名按不可信输入处理，不能直接作为服务器存储路径。
- JSON 解析限制嵌套深度和记录数量，避免异常文件耗尽内存。
- 对话内容在入库和发送给模型前都经过脱敏处理。
- 临时文件在确认或放弃后清理，不长期保留重复副本。

## 5. 与其他模块的关系

```text
上传 JSON -> 字段映射 -> 脱敏预览 -> 确认入库 -> 发起评测
```

数据采集不负责评分，也不直接产生问题、告警或 QA。所有后续模块都引用已经确认的数据批次。

## 6. 验收标准

1. 不固定结构的有效 JSON 可以通过人工映射转换成统一对话。
2. 预览确认前不会污染正式数据表。
3. 同一文件重复确认不会产生重复对话。
4. 错误记录和跳过数量在入库前后保持可见。
5. 入库完成后可以直接跳转到“发起评测”并选择该批次。
