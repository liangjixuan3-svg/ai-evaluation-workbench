# QA 审核工作台

## 1. 目标

把“问题与归因”中人工确认的知识缺失任务继续处理成可审核、可追溯、可下载的知识库 QA。首版面向单人维护场景，不直接写入外部知识库，不允许 AI 自动批准。

完整流程为：

```text
知识缺失任务
-> 按需生成 QA 草稿
-> 人工编辑并补充业务依据
-> 批准或驳回
-> 下载 JSON / CSV
-> 交给知识库团队发布
```

## 2. 页面方案

采用左侧队列、右侧详情的单页审核工作台，与“问题与归因”保持一致。

### 2.1 顶部概况

展示四项真实数量：待生成、待审核、已批准、已驳回。数量按 QA 审核任务统计，不使用演示数据。

### 2.2 左侧队列

支持筛选待处理、已批准、已驳回和全部。每项展示：

- 业务场景和问题摘要。
- 影响对话数量。
- 任务优先级。
- 当前状态：待生成、待审核、已批准或已驳回。
- 草稿置信度；尚未生成时显示“未生成”。

### 2.3 右侧详情

按以下顺序展示：

1. 问题事实：关联问题簇、影响数量、人工确认的知识缺失原因。
2. 代表证据：最多三条脱敏对话、评测分数和失败原因。
3. QA 草稿：建议问法、标准答案、适用条件、处理步骤、预计时效和转人工条件。
4. 审核区：业务依据、批准、驳回和下载操作。

## 3. Token 控制

- 创建知识缺失任务时不自动生成草稿。
- 只有人工点击“生成 QA 草稿”才调用真实模型。
- 同一任务已存在草稿时直接返回已有版本，重复点击不重复调用模型。
- 驳回不自动重新生成；首版由人工决定是否后续增加“重新生成”。
- 列表、详情、编辑、批准和下载均不调用模型。

## 4. 审核规则

### 4.1 草稿字段

- 建议问法 `question`
- 标准答案 `answer`
- 适用条件 `applicability`
- 处理步骤 `handling_steps`
- 预计时效 `estimated_time`
- 转人工条件 `escalation`

全部字段必填；处理步骤至少一项。页面允许在批准前直接编辑。

### 4.2 业务依据

批准前必须至少填写一条业务依据，每条包括：

- 来源名称：例如“退款规则 2026 V3”或内部制度链接。
- 原文摘录：能够支持标准答案的具体内容。

代表对话和 AI 归因属于问题证据，不等同于业务依据。缺少业务依据时批准按钮不可用，后端继续执行强校验。

### 4.3 状态流转

```text
待生成 -> 待审核 -> 已批准
                 -> 已驳回
```

- 待生成：已有 QA 审核任务，尚无草稿。
- 待审核：AI 草稿已生成，等待人工编辑和决定。
- 已批准：创建不可变的新版本，记录审核人和批准时间。
- 已驳回：记录驳回人、原因和时间，不允许下载。

首版批准或驳回后保持只读，避免破坏审计记录。

## 5. 下载方案

- 只有已批准版本可以下载。
- 支持单条下载 JSON 或 CSV。
- 下载内容继续使用现有 `qa-export-v1` 结构。
- 浏览器直接获得文件，不展示服务器本地路径。
- 每次下载保留导出记录；内容相同的重复导出继续复用现有幂等记录。

## 6. 接口设计

复用现有生成、批准和导出领域服务，新增面向页面的查询和操作接口：

- `GET /api/qa-workspace?status=...`：任务概况与队列。
- `GET /api/qa-workspace/{task_id}`：问题事实、代表样本、草稿当前版本和业务依据。
- `POST /api/qa-workspace/{task_id}/generate`：使用当前真实模型按需生成草稿。
- `POST /api/qa-drafts/{draft_id}/approve`：提交编辑内容和业务依据并批准。
- `POST /api/qa-drafts/{draft_id}/reject`：填写原因后驳回。
- `POST /api/qa-exports/download`：校验已批准版本并返回 JSON 或 CSV 文件。

真实模型配置沿用评测与归因使用的 `LLM_BASE_URL`、`LLM_API_KEY` 和 `LLM_MODEL`，不再使用当前路由中的假模型默认值。

## 7. 数据与审计

复用现有 `tasks`、`qa_drafts`、`qa_versions`、`qa_evidence`、`export_records` 和 `qa_export_items`。不新增核心表。

驳回状态使用现有 `QADraftStatus.REJECTED`。驳回人、原因和时间写入审计日志；批准继续创建新的不可变版本，不覆盖 AI 初稿。

## 8. 异常处理

- 模型未配置：生成按钮禁用，后端返回明确的 `503`。
- 模型调用失败：保留任务为待生成，允许人工稍后重试。
- 草稿字段不完整：前端提示具体字段，后端返回 `422`。
- 缺少业务依据：禁止批准并说明原因。
- 未批准草稿请求下载：拒绝下载。
- 页面加载失败：展示可重试错误状态，不停留在无限加载。

## 9. MVP 范围外

- 批量自动生成草稿。
- AI 自动批准或自动发布。
- 直接连接第三方知识库。
- 多人抢单、权限和复杂协同。
- 驳回后自动重生成。
- 批量下载多个 QA；首版先保证单条闭环。

## 10. 验收标准

1. 知识缺失任务可在 QA 审核页面看到，并能追溯到代表对话。
2. 点击生成时才发生一次真实模型调用，重复点击不重复调用。
3. 人工可编辑全部六个 QA 字段。
4. 没有业务依据不能批准；批准后形成新版本并保持历史初稿不变。
5. 驳回必须填写原因，驳回后不可下载。
6. 已批准 QA 可以从浏览器下载有效的 UTF-8 JSON 或 CSV。
7. 页面适配桌面和移动端，并符合全站可读性规范。
8. 后端测试、前端测试、Ruff 和生产构建通过。
