# JSON 数据采集与真实评测设计规格

> 确认日期：2026-07-30

## 1. 目标

在现有 AI 评测迭代工作台中补齐真正可执行的采集和评测入口，使运营人员无需固定 JSON 格式，也能完成：

```text
上传 JSON
-> 识别对话记录
-> 映射字段并预览
-> 脱敏、去重并写入 MySQL
-> 配置抽样与评测
-> 调用 OpenAI 兼容模型
-> 查看进度和逐条结果
-> 将失败案例送入现有 Badcase 与告警流程
```

本轮以单人维护、单台服务器和单批不超过 10,000 条对话为约束。

## 2. 产品入口

“评测运行”模块提供两个真实操作页面：

1. 数据采集：上传 JSON、识别结构、映射字段、预览并确认入库。
2. 发起评测：选择已入库批次、配置抽样和模板、启动任务并查看结果。

工作台首页和其他页面保持任务驱动，不把采集配置提升为新的一级导航。

## 3. JSON 数据采集

### 3.1 上传与解析

- 接受 UTF-8 JSON 文件，单文件最多 20 MB、最多 10,000 条对话。
- 支持根节点直接为数组，也支持记录数组位于对象内部，例如 `data.items` 或 `result.conversations`。
- 上传阶段只创建临时导入会话，不写入正式对话表。
- 后端返回候选数组路径、记录数量、字段路径建议和最多 10 条预览。
- 临时上传内容设置有效期，确认或放弃后清理，不长期保留重复文件。

### 3.2 字段映射

每条标准化对话需要以下字段：

- 外部对话 ID：必填；没有可用字段时允许按原始记录计算稳定哈希。
- 发生时间：必填；支持 ISO-8601 和常见时间戳。无法识别时必须人工指定时区或修正映射。
- 场景：可选。
- 状态：可选。
- 消息：必填。

消息支持两种模式：

1. 消息数组模式：映射消息数组、角色字段和内容字段。
2. 问答字段模式：分别映射用户问题和 AI 回答，系统转换为两条消息。

系统使用字段名和样例值进行本地启发式推荐，不调用大模型自动决定映射。未映射字段完整保留在原始正文中。

### 3.3 预览与确认

确认入库前展示：

- 原始记录与标准化消息对照。
- 场景、状态和时间解析结果。
- 手机号、订单号等敏感信息的脱敏预览。
- 缺失必填字段、无法解析记录和重复 ID 的数量。

存在错误记录时允许选择“阻止整批导入”或“跳过错误记录”；默认阻止，避免静默丢失数据。

### 3.4 正式入库

- 每次确认创建一个数据源和一个采集批次记录。
- 使用数据源 ID 与外部对话 ID 组成幂等键。
- 重复记录计入 skipped，已写入记录不被覆盖。
- 返回新增数、跳过数、错误数、批次 ID 和可进入评测的对话数量。
- 写入审计日志，记录文件名、文件哈希、映射版本和操作者，不记录 API Key。

## 4. 真实模型评测

### 4.1 模型配置

模型通过服务器环境变量配置：

```text
LLM_BASE_URL
LLM_API_KEY
LLM_MODEL
```

- 兼容 OpenAI Chat Completions 风格接口。
- API Key 只存在于服务器进程环境，不返回前端、不写入数据库、不进入日志。
- 页面只显示供应商地址是否已配置、模型名称和连接检查结果。
- 未配置或连接检查失败时禁止启动真实评测，并返回可执行的错误说明。

### 4.2 发起评测

运营人员选择：

- 已完成的数据采集批次。
- 抽样数量，不能超过批次可用记录数。
- 抽样策略：随机、风险优先或重点场景加权。
- 评测模板：首版提供内置客服质量模板。
- 通过阈值和模型参数；高级 Prompt 编辑不在本轮范围。

内置模板评测正确性、完整性、相关性、服务体验和合规性，并支持严重事实错误和严重合规错误一票否决。

### 4.3 后台执行

- 创建运行后立即返回运行 ID，不在一个 HTTP 请求内等待整批模型调用。
- 单服务器使用现有 MySQL 任务队列和 Worker，不增加 Redis 或独立工作流引擎。
- Worker 按单条对话执行模型调用，保存检查点；单条失败不阻断同批其他记录。
- 临时错误指数退避，超过重试上限进入人工处理。
- 每次模型调用记录模型、耗时、token 数、估算成本、状态和错误码。
- 发送给模型前使用现有脱敏逻辑，模型不接收未脱敏原文。

### 4.4 结构化输出

模型必须返回可校验 JSON：

- 五个维度的分数。
- 评测理由。
- 来自对话原文的证据片段。
- 置信度。
- 严重事实错误和严重合规错误标记。

供应商返回必须通过现有 `EvaluationProvider` 验证边界。非 JSON、缺字段、非法分数或证据无法在脱敏对话中定位时，当前记录视为失败并进入重试，不生成不可信的正式结果。

## 5. 运行进度与结果

运行详情按以下阶段展示：

```text
采集完成 -> 抽样完成 -> 模型评测 -> Badcase 聚类 -> 告警生成 -> 等待人工处理
```

页面轮询稳定的运行详情 API，展示：

- 总样本数、已完成数、通过数、失败数和待重试数。
- 当前阶段、开始时间、耗时和最近错误。
- 通过率、平均分和五维平均分。
- 逐条对话的分数、通过状态、理由和证据。
- 失败调用的错误摘要与重试状态。

模型评测完成后，失败案例进入现有 Badcase 聚类和告警服务。根因确认及 QA 审核仍由人工完成；流水线不得自动批准或发布 QA。

## 6. 后端边界

新增应用层接口分为三组：

1. 导入会话：上传、结构分析、映射预览、确认和放弃。
2. 评测操作：读取可选批次和模型状态，创建一键评测运行。
3. 运行查询：运行列表、阶段进度、聚合指标和分页结果。

导入解析、字段映射、OpenAI 兼容传输和运行编排保持独立模块，前端不直接拼装数据库实体或模型 Prompt。

需要新增采集批次元数据时使用独立 Alembic 迁移；不修改历史迁移文件。

## 7. 前端交互

### 7.1 数据采集页面

采用四步操作区：

1. 上传 JSON。
2. 选择记录数组和字段映射。
3. 查看标准化与脱敏预览。
4. 确认入库并显示结果。

页面保留现有暖色操作台视觉语言，使用清晰的步骤状态、错误行定位和固定主操作，不复制参考图的暗色样式。

### 7.2 发起评测页面

左侧为批次、抽样、模板和模型参数；右侧为执行阶段、核心数量和实时日志摘要。启动按钮必须明确显示预计样本数和将使用的模型。

运行中禁止重复提交同一配置；刷新页面后通过运行 ID 恢复状态。

## 8. 异常与安全

- 非 JSON、超出大小限制、找不到记录数组或映射不完整时不创建正式数据。
- 文件名按不可信输入处理，不直接用于服务器路径。
- JSON 解析限制深度和记录数量，防止异常文件占满内存。
- 外部对话 ID、时间和消息内容在写入前进行类型与长度校验。
- 模型调用设置连接与响应超时，错误响应不包含 API Key 或完整对话正文。
- 导入和评测接口保留幂等键，页面重复点击不会重复入库或重复计费。

## 9. 测试与验收

### 9.1 测试

- 单元测试覆盖数组路径发现、两种消息映射、时间解析、稳定哈希、错误记录策略和模型响应验证。
- 集成测试覆盖临时导入确认、MySQL 去重、运行创建、后台执行、部分失败和进度查询。
- 前端测试覆盖四步采集、映射错误、启动评测和运行状态恢复。
- 使用假传输测试模型适配器，不在自动测试中调用付费 API。

### 9.2 验收标准

1. 任意结构的有效 JSON 可通过人工映射转换为统一对话结构。
2. 预览确认前不会污染正式数据表。
3. 同一文件重复确认不会产生重复对话。
4. 配置 OpenAI 兼容环境变量后可真实调用模型并保存逐条结果。
5. 单条模型失败不影响同批其他结果，页面能看到失败与重试状态。
6. 页面刷新后仍能通过运行 ID 查看真实进度和结果。
7. API Key 不出现在前端、数据库、审计日志或错误响应中。
8. 评测失败案例可继续进入现有 Badcase、告警和人工改进闭环。

## 10. 本轮非目标

- HTTP 数据源定时拉取。
- Excel 或 CSV 导入。
- AI 自动决定字段映射。
- 多租户、复杂权限和任务审批流。
- 在线高级 Prompt 编辑。
- 自动批准或自动发布 QA。
