# 发布与复测

## 目标

把审核通过的 QA 从“改进建议”推进到“已上线并验证有效”，形成问题闭环。首版采用严格双样本复测，同时提供演示数据走通完整流程。

## 用户流程

1. 在“待发布”中选择已批准且关联问题告警的 QA。
2. 填写发布人、发布时间和发布备注，登记为已发布。
3. 系统自动创建复测任务，并锁定原评测使用的公司质量标准、评测 Prompt、模型和通过阈值。
4. 系统准备两组样本：历史失败对话用于回放，发布时间后的同场景线上对话用于新增观察。
5. 两组样本达到最低数量后执行评测；不足时显示“等待新样本”，不提前关闭问题。
6. 两组通过率都达到阈值时标记“改善有效”并关闭问题，否则标记“仍需改进”。

## 页面结构

侧边栏“04 发布与复测”进入同一工作台，顶部显示待发布、等待样本、复测中、改善有效和仍需改进数量。

- 待发布：展示 QA 问题、场景、版本和批准时间，提供“登记发布”。
- 复测任务：展示两组样本准备进度、锁定规则版本和执行入口。
- 复测结果：对比发布前、历史回放和新增样本通过率，展示结论与后续动作。

### 工作台摘要

每张复测任务卡片增加“复测方法”摘要，直接说明本次复测如何执行：

- 样本：历史回放与发布后新对话各有多少条、最低要求多少条。
- 裁判：锁定的公司质量标准版本、评测 Prompt 版本和模型。
- 判定：单条得分阈值、两组通过率阈值，以及“两组都达标才算改善有效”。
- 入口：有样本时显示“查看复测明细”，查看过程不重新调用模型、不产生额外费用。

### 复测详情页

路径使用 `/retests/{复测任务ID}`，顶部先给出人能读懂的结论解释，再展示逐条样本。

- 结论解释：例如“历史回放 9/10 通过，新对话 8/10 通过；两组均达到 80%，因此判定改善有效”。未完成时解释还缺哪一组、多少条样本。
- 方法说明：展示样本选择方式、公司质量标准、Prompt、模型、单条阈值和组阈值。
- 样本筛选：支持查看全部、历史回放、发布后新对话，并显示各组通过数和失败数。
- 逐条结果：展示对话时间、用户问题、AI 回复、总分、通过状态、五项维度分、评测理由、证据以及严重事实或合规错误。
- 失败样本优先：默认先显示未通过样本，再按总分从低到高排列，方便直接定位问题。

## 数据与接口

复用现有 `RetestSample`、`Conversation` 和 `EvaluationResult`，不新增结果表，也不重新评测。

- 工作台详情继续返回任务摘要，并增加可跳转的明细入口条件。
- `GET /api/retest-workspace/{run_id}` 返回复测过程、结论解释和逐条样本结果。
- 每条样本返回所属组、对话内容、发生时间、总分、维度分、理由、证据、置信度和严重错误标记。
- 尚未产生结果的样本仍返回对话和“待评测”状态，避免用户误以为样本没有被选中。

## 计算口径

- 单条通过：模型返回的维度分按原评测模板权重计算总分，达到单条阈值且未触发否决规则。
- 组通过率：该组通过样本数除以该组已完成样本数。
- 改善有效：历史回放通过率和发布后新对话通过率都达到组通过率阈值。
- 页面展示的数字必须直接来自持久化结果，不能由前端重新推断另一套口径。

## 异常与空状态

- 样本不足：展示缺少的组和数量，不显示误导性的最终结论。
- 尚未评测：展示已选样本及“待评测”，不显示维度分和评测理由。
- 部分失败：保留已成功结果，明确显示未完成数量和“可继续复测”。
- 旧数据缺少结果：显示“历史记录暂无逐条结果”，工作台汇总仍保持可见。
- 找不到任务：返回中文错误页，并提供返回“发布与复测”的入口。

## 验收标准

1. 用户从工作台无需阅读代码即可说清本次复测使用了哪些样本、规则、Prompt、模型和阈值。
2. 用户可以打开任一复测任务，查看每条样本的原对话、总分、维度分、理由和证据。
3. 页面能用通过数、总数和阈值解释“改善有效”或“仍需改进”的原因。
4. 查看明细不会发起模型请求，也不会增加模型费用。
5. 历史回放和发布后新对话可以独立筛选，未通过样本默认优先展示。

## 状态规则

- `待发布`：QA 已批准，尚未登记上线。
- `等待新样本`：已发布，但任一组样本未达到最低数量。
- `待执行`：两组样本已满足最低数量，可开始复测。
- `复测中`：模型正在逐条评测。
- `执行已中断`：任务超过 30 分钟没有进度，可从已保存结果继续，不重复评测成功样本。
- `改善有效`：两组通过率均达到阈值，问题关闭。
- `仍需改进`：至少一组未达到阈值，问题保留并回到改进队列。

## 演示数据

演示数据包含一条可发布 QA、关联告警、历史失败样本和发布后的同场景新样本。它只用于展示完整闭环，不改变真实业务必须等待线上新对话的规则。

## 首版边界

- 发布登记代表外部知识库已上线，不直接调用企业知识库发布接口。
- 复测由用户在页面手动触发，单台服务器串行处理，适配每日少于一万条对话。
- 页面同时展示单条得分阈值和两组通过率阈值，避免混淆结论标准。
- 不增加消息队列或独立调度服务，沿用现有数据库、评测 Provider 和审计记录。
