# QA 演示数据

## 目标

向当前开发数据库加入一组可重复使用的 QA 审核演示数据，让“待生成、待审核、已通过、已驳回”四种页面状态同时可见。演示过程不调用大模型，不消耗 Token，也不改变真实业务数据。

## 实现方式

新增 `backend/scripts/加入QA演示数据.py`，直接复用项目 SQLAlchemy 模型写入完整关联数据。脚本提供两种操作：

- 默认执行：加入或修复演示数据。
- `--清理`：只删除由该脚本创建的演示数据。

脚本使用固定的数据源名称、外部对话编号和问题簇分组标识识别自己的数据。每次执行前先检查已有记录，重复运行不会继续增加数量。

## 演示场景

| 状态 | 场景 | 页面可体验内容 |
| --- | --- | --- |
| 待生成 | 物流异常催单 | 查看失败证据并按需生成 QA 草稿 |
| 待审核 | 退款进度查询 | 编辑六项 QA 内容、填写业务依据、通过或驳回 |
| 已通过 | 发票开具咨询 | 查看锁定版本并下载 JSON 或 CSV |
| 已驳回 | 商品信息咨询 | 查看驳回原因和已关闭任务 |

每个场景包含一条评测失败结果、一个问题簇、人工确认的知识缺失归因和一条 QA 审核任务。后三种状态还包含 QA 草稿与版本；已通过数据额外包含业务依据，已驳回数据额外包含驳回原因。

## 数据安全

- 仅连接 `backend/.env` 中配置的开发数据库。
- 脚本启动时显示数据库主机和库名，但不显示密码。
- 写入和清理均放在事务中，失败时整体回滚。
- 清理操作只匹配 `qa-demo-*` 外部编号和 `qa-demo-*` 分组标识，不按业务类型批量删除。
- 不调用 DeepSeek，不创建真实导出记录，不覆盖用户已有数据。

## 验收标准

1. 第一次执行后，QA 工作台四项统计各至少增加一条。
2. 第二次执行后，演示任务数量不变。
3. 四个筛选页分别能打开对应任务详情。
4. 已通过任务可下载，待审核任务可继续人工操作。
5. 执行 `--清理` 后只移除本脚本加入的数据。
