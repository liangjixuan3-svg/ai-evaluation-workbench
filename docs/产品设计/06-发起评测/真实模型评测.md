# 真实模型评测

## 1. 模块目标

从已入库的对话批次中抽取样本，使用已发布的公司质量标准和评测 Prompt 调用真实模型，保存可追溯的逐条评分、理由和证据，并把失败案例送入问题归因闭环。

## 2. 页面入口

左侧导航“06 发起评测”，路由为 `/runs/new`。运行创建后进入 `/runs/{运行ID}` 查看实时进度和结果。

## 3. 运行前提

发起评测前必须具备：

1. “数据采集”中已确认入库的数据批次。
2. “评测规则”中已发布的公司质量标准。
3. “评测规则”中已发布的评测 Prompt。
4. 后端 `.env` 已配置 `LLM_BASE_URL`、`LLM_API_KEY` 和 `LLM_MODEL`。
5. 后端 API 和评测 Worker 正在运行。

API Key 只存在于后端配置，不返回前端、不写入数据库，也不进入日志。

## 4. 评测配置

用户需要选择：

- 数据批次和抽样数量。
- 抽样策略：风险优先、场景均衡或纯随机。
- 已发布的公司质量标准版本。
- 已发布的评测 Prompt 版本。
- 模型参数中系统允许调整的安全字段。

通过阈值、五维权重、评分规则和一票否决条件来自所选公司标准，不能在本页临时篡改。每次运行锁定数据批次、抽样配置、标准版本、Prompt 版本、模型和参数，后续规则更新不会改写历史结果。

## 5. 后台执行

- 创建运行后立即返回运行 ID，不让一个 HTTP 请求等待整批模型调用。
- Worker 使用 MySQL 任务队列逐条处理，不依赖 Redis 或独立工作流引擎。
- 单条失败不阻断同批其他样本；临时错误会重试，超过上限后保留错误摘要。
- 每次模型调用记录模型、耗时、Token 数、估算成本、状态和错误码。
- 对话发送给模型前使用统一脱敏逻辑。

## 6. 模型输出与评分

模型必须返回可校验的结构化结果：

- 正确性、完整性、相关性、服务体验、合规性五个维度分数。
- 总分和通过/不通过结论。
- 具体评测理由和来自对话的证据。
- 置信度。
- 严重事实错误和严重合规错误标记。

供应商返回非 JSON、缺少字段、分数越界或证据无法定位时，该样本评测失败并进入重试，不生成看似完整但不可信的正式结果。

## 7. 运行详情

页面持续展示：

- 总样本数、完成数、通过数、失败数和待重试数。
- 当前阶段、开始时间、耗时和最近错误。
- 通过率、平均分和五维平均分。
- 每条对话的分数、结论、评测理由和引用证据。
- 本次锁定的公司标准、Prompt 和模型版本。

刷新页面不会重新发起评测，而是根据运行 ID 恢复已有进度。

## 8. 后续流转

```text
真实评测 -> 不合格案例 -> 问题聚类与归因 -> QA 或其他改进任务
```

模型评测完成后，不合格案例进入“问题与归因”。系统不会自动确认根因、批准 QA 或发布知识库内容。

## 9. 异常处理

- 模型未配置时禁止启动，并指出缺少的环境变量。
- 没有可用数据、标准或 Prompt 时禁用启动按钮，并提供对应页面入口。
- 相同配置重复提交时使用幂等控制，避免重复请求和重复计费。
- Worker 中断后保留已完成结果，恢复时只处理尚未完成的样本。
- 错误信息不得包含 API Key 或完整未脱敏对话。

## 10. 验收标准

1. 可以选择真实数据批次和已发布规则发起评测。
2. 单条模型失败不影响其他样本完成。
3. 页面刷新后仍可查看真实进度和结果。
4. 每条结论都能追溯到对话、标准、Prompt、模型和证据。
5. 不合格案例能够继续进入问题归因流程。
