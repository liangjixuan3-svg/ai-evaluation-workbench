# 公司质量标准配置设计

## 目标

让运营人员上传公司的 Word 或 PDF 质检规范，由 AI 提取为可审核的结构化评测规则。规则必须经人工确认并发布为不可变版本，评测运行绑定具体版本，使分数能够解释、复现和追溯。

## MVP 范围

- 支持 `.docx` 和含可复制文字的 `.pdf`。
- 不支持扫描件 OCR、旧版 `.doc`、在线文档地址和多文件合并。
- 从文档中识别通用规则与场景规则。
- 保留每条规则对应的原文、页码或段落位置。
- 人工可以修改、停用或删除 AI 提取的草稿规则。
- 发布后生成不可修改的版本；修改已发布规则必须创建新版本。
- 发起评测时选择一个已发布的标准版本，默认选择最新版本。

## 产品流程

左侧已有的“评测规则”菜单替换为真实功能，包含规则列表和四步创建向导。

1. **上传文档**：填写标准名称并上传 Word/PDF。系统检查格式、大小、是否能提取文字和文件哈希。
2. **AI 解析**：后台任务提取文本、分段调用模型、合并重复规则，生成通用规则、场景规则和需要人工确认的疑似规则。
3. **人工审核**：页面左侧显示原文出处，右侧编辑结构化规则。所有高风险或低置信度规则必须逐条确认。
4. **发布版本**：通过完整性检查后发布为 `v1`、`v2` 等版本，并显示规则数量、适用场景和发布时间。

规则列表展示草稿、解析中、解析失败、已发布四种状态。已发布版本可以查看和复制为新草稿，但不能直接修改。

## 规则结构

一个标准版本由以下部分组成：

- 基本信息：名称、版本、来源文件、文件哈希、适用业务、通过阈值。
- 五个固定维度：准确性、完整性、相关性、服务体验、合规性。
- 维度权重：总和必须为 100%。
- 分档描述：每个维度至少配置 100、80、60、40、0 五档含义。
- 通用规则：适用于所有场景，例如隐私保护、禁止虚假承诺、服务态度。
- 场景规则：例如退款进度查询、物流异常催单的业务步骤。
- 规则效果：普通要求、维度分数上限或一票否决。
- 原文出处：引用原文、页码或段落编号，供审核和结果解释使用。

MVP 保持现有五个维度不变。AI 可以建议权重和分档，但发布前必须人工确认。

## 评分执行

发起评测时，运行记录保存标准版本 ID、模型版本和数据批次。后台只向模型提供本次场景相关的通用规则和场景规则，不发送整份文档，以控制 token 消耗。

模型返回：

- 五个维度分数。
- 每条适用规则的 `满足 / 不满足 / 不适用` 判定。
- 判定理由和对话原文证据。
- 严重事实错误、严重合规错误和置信度。

后端负责最终计算，模型不能直接决定总分：

1. 按标准版本中的权重计算五维加权分。
2. 对未满足的“分数上限”规则应用对应维度上限。
3. 命中一票否决规则时直接判失败。
4. 最终分达到标准版本阈值且未被否决时判定通过。

置信度只用于提示人工复核，不参与总分。未知场景只应用通用规则，并在结果中显示“缺少场景标准”提示。

## 数据与服务边界

- `quality_standards`：标准主体和当前状态。
- `quality_standard_versions`：不可变版本、结构化规则 JSON、来源元数据和发布时间。
- `quality_standard_parse_jobs`：文档解析任务状态、错误摘要和重试次数。
- 原始上传文件保存在服务器受控目录，数据库只保存路径、哈希和元数据。
- 评测运行保存 `quality_standard_version_id`，历史结果不随新版本变化。

解析复用现有 MySQL 任务队列和 Worker，避免上传请求长时间阻塞。文档文本提取和规则提取分别封装，后续增加 OCR 时不影响规则审核与评测模块。

## 错误处理与安全

- 文件扩展名、MIME 类型和实际内容必须一致。
- 文件大小第一版限制为 20 MB。
- 文档无可提取文字时明确提示“可能是扫描版 PDF”，不调用模型。
- 模型解析失败可以重试，不重复创建标准版本。
- 低置信度、来源缺失或冲突规则标记为“待确认”，禁止自动发布。
- 上传文件名重新生成，禁止使用用户路径，文档内容不写入普通运行日志。
- 删除草稿时清理对应文件；已发布版本及其来源文件保留用于审计。

## 测试与验收

- 单元测试覆盖 Word/PDF 文本提取、规则结构校验、权重校验、版本不可变和评分上限/否决逻辑。
- 集成测试覆盖上传、异步解析、人工编辑、发布、发起评测和历史版本追溯。
- 前端测试覆盖四步状态恢复、错误提示、规则出处对照、禁止发布条件和版本选择。
- 使用退款与物流两份固定样例文档做回归测试，确保解析结果结构稳定。

验收标准：运营人员无需编辑 Prompt，即可从 Word/PDF 创建并发布质量标准；新评测明确绑定标准版本；每个失败结果能够显示命中的公司规则及其文档出处。
