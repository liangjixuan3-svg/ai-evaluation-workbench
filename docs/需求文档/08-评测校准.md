# 08 评测校准需求

## 1. 模块目标

让运营人员持续复核模型评测是否可信，记录人机分歧，并把不认同案例沉淀为后续规则和 Prompt 回归案例。

## 2. 使用角色与场景

- 角色：质检人员、AI 产品经理和评测规则负责人。
- 场景：真实评测完成后，每日抽查高价值案例，检查模型裁判质量。

## 3. 前置条件

- 最近 7 天存在完成的真实评测结果。
- 校准过程不要求模型服务可用。

## 4. 核心功能需求

1. 每天幂等创建一个最多 20 条的校准批次。
2. 优先抽取低置信度、阈值边界、严重错误和少量随机案例。
3. 展示脱敏对话、模型结论、五维分、理由、证据和锁定版本。
4. 用户可以填写审核人并认同模型判定。
5. 用户可以提交正确结论、分歧维度和人工依据表示不认同。
6. 展示今日进度、人机一致率和主要分歧维度。
7. 不认同案例自动加入回归集合。

## 5. 关键业务规则

- 当天重复进入页面不能重复创建批次或案例。
- 同一评测结果首版只进入一个校准批次。
- 校准抽样、浏览和提交均不调用模型，不消耗 Token。
- 人工结论独立保存，不覆盖原始评测结果。
- 不认同时必须填写正确结论、主要分歧维度和人工依据。
- 已提交结果保持只读，不能无痕修改。

## 6. 页面状态与异常

- 没有可复核结果时引导用户先完成真实评测。
- 案例不足 20 条时显示实际数量，不视为错误。
- 重复提交返回已有结果，不重复写入。
- 引用的评测或对话缺失时说明数据异常。
- 已复核数为零时一致率显示“待复核”，不显示 0%。

## 7. 验收标准

1. 每天最多生成一个校准批次。
2. 用户能核对对话、理由、证据和评测版本。
3. 认同和不认同操作按规则完成校验。
4. 人工复核不会修改原始评测结果。
5. 一致率和主要分歧维度计算准确。
6. 不认同案例自动进入回归集合。
7. 整个流程不产生模型调用。

## 8. 暂不包含

- 人工重新打全部维度分。
- 双人复核、仲裁和任务分配。
- 自动修改或发布 Prompt、公司标准。
- 本期直接执行跨版本回归评测。
