# 07 评测规则需求

## 1. 模块目标

让运营人员维护“评什么”和“模型如何评”，并通过不可变版本保证每次评测可以解释、复现和追溯。

## 2. 使用角色与场景

- 角色：AI 产品经理、质检负责人和业务规则维护人员。
- 场景：首次配置评测标准、公司制度更新或需要调整模型评测指令时。

## 3. 前置条件

- 公司标准来源为 `.docx` 或含可复制文字的 `.pdf`。
- AI 解析文档时后端模型配置可用。

## 4. 核心功能需求

### 4.1 公司质量标准

1. 上传公司制度文档并提取结构化规则草稿。
2. 展示通过阈值、五维权重、评分说明、通用规则和场景规则。
3. 每条规则展示制度原文引用和位置。
4. 用户可以修改、停用、删除或确认草稿规则。
5. 完整校验后发布为锁定版本。
6. 用户可以查看历史版本的完整规则内容。

### 4.2 评测 Prompt

1. 系统提供可用的内置 V1。
2. 展示已发布版本和当前默认版本。
3. 用户可以复制已发布版本生成新草稿。
4. 草稿可以保存、继续编辑并发布。
5. 发起评测时可以选择任一已发布版本。

## 5. 关键业务规则

- 公司标准负责“评什么”，Prompt 负责“模型怎样判断和解释”。
- 五个评分维度、结构化输出和安全校验由系统固定。
- 五维权重合计必须为 100%。
- 低置信度、来源缺失和冲突规则必须人工确认。
- 未确认完整的公司标准不能发布。
- 已发布标准和 Prompt 不可修改或删除；修改必须创建新版本。
- 历史评测始终保留原版本引用。

## 6. 页面状态与异常

- 扫描版 PDF 或无可提取文字的文档提示无法解析，不调用模型。
- AI 解析失败允许重试，但不重复创建版本。
- 空 Prompt、超长 Prompt 或与已发布版本完全相同的内容不能发布。
- 草稿不能参与真实评测。
- 版本内容无效时明确指出需要修正的部分。

## 7. 验收标准

1. 用户可以从 Word/PDF 创建并发布公司标准。
2. 每条规则可以追溯到制度原文。
3. 用户可以复制、编辑并发布新的 Prompt 版本。
4. 已发布版本保持只读，历史版本可查看。
5. 发起评测只能选择已发布规则，并保存实际使用版本。

## 8. 暂不包含

- 扫描件 OCR、旧版 `.doc` 和在线文档地址。
- AI 自动发布规则或自动优化 Prompt。
- 在线 A/B 实验和自动效果对比。
- 修改模型输出协议和核心评分字段。
