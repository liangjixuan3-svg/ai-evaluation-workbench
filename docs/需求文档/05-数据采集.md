# 05 数据采集需求

## 1. 模块目标

把字段结构不固定的客服对话 JSON 转换成统一、脱敏、可评测的数据批次。

## 2. 使用角色与场景

- 角色：客服运营、数据运营和 AI 产品经理。
- 场景：从业务系统导出一批对话，需要导入工作台进行评测。

## 3. 前置条件

- 用户准备 UTF-8 JSON 文件。
- 单文件不超过 20 MB，单批不超过 10,000 条对话。

## 4. 核心功能需求

1. 上传 JSON 并识别可能的对话记录数组。
2. 推荐对话 ID、时间、场景、状态和消息字段映射。
3. 支持消息数组和用户问题/AI 回答两种消息结构。
4. 展示原始记录、标准化对话和脱敏结果预览。
5. 统计缺失字段、解析失败和重复记录。
6. 用户确认后写入正式数据并生成数据批次。
7. 入库完成后可以继续进入发起评测。

## 5. 关键业务规则

- 上传和预览阶段不得写入正式对话表。
- 自动映射仅作为建议，最终由用户确认。
- 默认存在错误记录时阻止整批入库；用户可明确选择跳过错误记录。
- 数据源 ID 与外部对话 ID 共同去重。
- 重复导入不得覆盖已有对话。
- 手机号、订单号等敏感信息必须脱敏。

## 6. 页面状态与异常

- 非 JSON、文件过大或找不到记录数组时停止导入并说明原因。
- 必填字段映射不完整时不能进入确认入库。
- 无法解析时间或消息时标记具体错误记录。
- 临时文件在确认或放弃后清理。

## 7. 验收标准

1. 不固定结构的有效 JSON 可以通过人工映射完成入库。
2. 确认前不会污染正式数据。
3. 重复文件不会产生重复对话。
4. 用户能在入库前看清标准化和脱敏结果。
5. 入库结果明确显示新增、跳过和错误数量。

## 8. 暂不包含

- CSV、Excel 和非 JSON 文件导入。
- AI 自动决定字段映射。
- HTTP 数据源定时拉取。
- 扫描图片或音视频对话解析。
