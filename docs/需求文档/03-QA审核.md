# 03 QA 审核需求

## 1. 模块目标

把人工确认的知识缺失问题转化为可审核、可追溯、可导出的知识库 QA，同时避免 AI 自动发布不可靠内容。

## 2. 使用角色与场景

- 角色：知识库运营、客服运营和质量负责人。
- 场景：问题归因确认为知识缺失后，需要形成可交付给知识库团队的标准答案。

## 3. 前置条件

- “问题与归因”已经创建知识缺失 QA 任务。
- 生成草稿时后端模型已配置。

## 4. 核心功能需求

1. 展示待生成、待审核、已批准和已驳回任务。
2. 展示问题事实、代表对话和人工确认的知识缺失原因。
3. 用户点击后生成一次 QA 草稿。
4. 草稿包含问题、答案、适用范围、处理步骤、预计时效和转人工条件。
5. 用户可以在批准前编辑所有草稿字段并补充业务依据。
6. 用户可以批准或填写原因后驳回草稿。
7. 已批准版本支持下载 JSON 或 CSV。

## 5. 关键业务规则

- 创建任务时不自动调用模型。
- 同一任务已有草稿时不得重复调用模型。
- 批准前所有 QA 字段必须完整，处理步骤至少一项。
- 业务依据必须同时包含来源名称和支持答案的原文。
- 代表对话和 AI 归因不能替代公司业务依据。
- 批准或驳回后内容锁定并保留审核记录。
- 只有已批准版本可以下载。

## 6. 页面状态与异常

- 模型未配置时禁用生成按钮。
- 模型调用失败时任务保持待生成并允许重试。
- 字段或业务依据不完整时指出具体缺失项。
- 未批准内容请求下载时拒绝操作。
- 页面加载失败时提供重新加载入口。

## 7. 验收标准

1. 知识缺失任务可以追溯到代表对话。
2. 草稿只在用户点击后生成一次。
3. 用户可以编辑完整 QA 内容和业务依据。
4. 无业务依据时不能批准。
5. 已批准 QA 可以下载有效的 UTF-8 JSON 或 CSV。

## 8. 暂不包含

- 自动批准、自动发布或直接连接知识库。
- 批量生成和批量下载。
- 驳回后自动重新生成。
- 多人协同审批和权限流。
