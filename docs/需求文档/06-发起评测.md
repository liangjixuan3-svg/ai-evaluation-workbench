# 06 发起评测需求

## 1. 模块目标

从已入库对话中抽样，使用已发布公司标准和评测 Prompt 调用真实模型，生成可追溯的质量评测结果。

## 2. 使用角色与场景

- 角色：AI 产品经理、客服运营和质检人员。
- 场景：新数据入库后，主动发起一次质量评测并查看结果。

## 3. 前置条件

- 已有确认入库的数据批次。
- 已发布公司质量标准和评测 Prompt。
- 后端模型配置、API 和评测 Worker 可用。

## 4. 核心功能需求

1. 选择数据批次和抽样数量。
2. 选择风险优先、场景均衡或纯随机抽样策略。
3. 选择已发布的公司标准和评测 Prompt。
4. 展示运行前检查和预计模型请求数量。
5. 启动异步评测并立即返回运行页面。
6. 展示进度、通过率、平均分、维度分和最近错误。
7. 展示逐条评分、结论、理由、证据和置信度。
8. 评测结束后把不合格案例送入问题归因流程。

## 5. 关键业务规则

- 每次运行必须锁定数据、抽样、标准、Prompt、模型和参数版本。
- 阈值、五维权重和否决规则来自公司标准，不能在本页临时修改。
- 单条失败不得中断整批任务。
- 重复提交不得造成重复运行或重复计费。
- 对话发送给模型前必须脱敏。
- 模型输出必须通过结构、分数范围和证据校验。

## 6. 页面状态与异常

- 缺少数据、规则、Prompt 或模型配置时禁用启动按钮并提供处理入口。
- Worker 中断时保留已完成结果，恢复后继续未完成样本。
- 单条模型输出不合格时进行有限重试，并展示失败摘要。
- 页面刷新后根据运行 ID 恢复状态，不重新发起任务。

## 7. 验收标准

1. 用户可以基于真实数据和已发布规则启动评测。
2. 页面能持续展示真实进度和逐条结果。
3. 单条失败不会影响其他样本完成。
4. 每条结果能追溯到当时使用的规则、Prompt 和模型。
5. 不合格结果能继续进入问题归因。

## 8. 暂不包含

- 全量线上流量实时评测。
- 多模型并行竞赛和自动选模。
- 页面修改 API Key。
- 自动批准后续归因和改进任务。
