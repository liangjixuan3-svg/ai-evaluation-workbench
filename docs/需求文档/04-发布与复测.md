# 04 发布与复测需求

## 1. 模块目标

把审核通过的改进内容推进到“已发布并验证效果”，确保问题只有在真实复测达标后才关闭。

## 2. 使用角色与场景

- 角色：知识库运营、AI 产品经理和质量负责人。
- 场景：QA 或其他改进已经在外部系统上线，需要登记并验证质量是否恢复。

## 3. 前置条件

- 已存在审核通过的 QA 或可发布改进项。
- 外部知识库或业务系统已经完成真实发布。
- 复测时模型配置可用。

## 4. 核心功能需求

1. 展示待发布 QA，并允许填写发布人和发布备注后登记发布。
2. 发布后创建复测任务并锁定原评测使用的规则、Prompt、模型和阈值。
3. 准备历史失败案例和发布后同场景新对话两组样本。
4. 展示每组样本数量、最低要求和当前准备状态。
5. 两组样本满足要求后允许启动复测。
6. 展示发布前、历史回放和新增样本通过率对比。
7. 提供逐条复测明细、理由、证据和最终结论解释。

## 5. 关键业务规则

- 发布登记代表内容已在外部系统上线，本产品不负责直接发布。
- 历史回放和新增样本必须分别达到最低数量。
- 两组通过率都达到锁定阈值，才判定“改善有效”。
- 任一组未达标则判定“仍需改进”，问题不得关闭。
- 查看复测明细不得重新调用模型。
- 中断恢复时只处理尚未完成的样本。

## 6. 页面状态与异常

- 样本不足时显示缺少的组和数量。
- 尚未评测的样本显示“待评测”，不得展示临时分数。
- 部分失败时保留已完成结果并允许继续。
- 超过规定时间无进度时显示“执行已中断”。
- 历史记录缺少逐条结果时保留汇总并明确说明。

## 7. 验收标准

1. 用户能说清每次复测使用的样本、规则、Prompt、模型和阈值。
2. 两组样本均达标时才能关闭问题。
3. 用户可以查看每条样本的对话、分数、理由和证据。
4. 结论可以通过通过数、总数和阈值进行解释。
5. 查看详情不会增加模型费用。

## 8. 暂不包含

- 直接调用企业知识库发布接口。
- 自动定时复测和复杂调度服务。
- 多版本并行实验和统计显著性分析。
