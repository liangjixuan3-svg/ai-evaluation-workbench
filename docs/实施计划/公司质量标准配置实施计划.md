# 公司质量标准配置实施计划

> **执行要求：** 使用测试驱动方式逐项实施，每项完成后单独验证并提交。

**目标：** 支持运营人员上传 Word/文本 PDF，经 AI 解析、人工审核后发布为版本化公司质量标准，并在真实评测中使用该标准。

**架构：** 在现有 FastAPI 单体中新增 `quality_standards` 模块，文档文件存储在本机受控目录，元数据和不可变规则版本存入 MySQL。解析任务复用现有数据库 Worker；前端将 `/rules` 占位页替换成四步向导。评测运行只读取已发布版本，并保存版本 ID 以保证追溯。

**技术栈：** Python 3.12、FastAPI、SQLAlchemy、Alembic、MySQL、python-docx、pypdf、React、TypeScript、Vitest。

## 全局约束

- 文件和页面文案使用中文；产品设计放 `docs/产品设计/`，实施计划放 `docs/实施计划/`。
- 只支持 `.docx` 和含可复制文字的 `.pdf`，单文件最大 20 MB。
- AI 只能生成草稿，未经人工确认不得发布或参与评测。
- 已发布版本不可修改；评测运行必须记录具体标准版本。
- 保持现有五个评分维度，权重总和必须为 1。
- 扫描版 PDF 第一版不做 OCR。
