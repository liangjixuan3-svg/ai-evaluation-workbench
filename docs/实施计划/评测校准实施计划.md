# 评测校准实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans` 逐任务实施。每一步使用复选框跟踪，并严格测试先行。

**目标：** 新增一个每天自动准备最多 20 条案例的人工评测校准工作台，记录人机一致与分歧，且不覆盖原始模型结果、不调用模型服务。

**架构：** 后端新增独立 `calibration` 模块，负责每日批次、分层抽样、只读详情和人工复核；使用 `calibration_batches` 与 `calibration_reviews` 保存状态，通过现有 `EvaluationResult` 追溯模型结果。前端新增独立校准 API 和“左侧队列、右侧复核”页面；当天批次由页面调用幂等 POST 创建，不新增定时进程。

**技术栈：** Python 3.12、FastAPI、SQLAlchemy 2、Alembic、MySQL 8、React 19、TypeScript、Vitest。

## 实施状态

- Task 1 至 Task 4 已完成：校准记录、每日分层抽样、中文复核接口和校准工作台均已实现并纳入自动测试。
- Task 5 的使用说明和自动回归已完成；人工页面验收尚未执行，需由用户手动启动后端 API、评测 Worker 和网页后，按本计划的验收项操作确认。

## 全局约束

- 每天最多准备 20 条，候选范围为最近 7 天已完成的评测结果。
- 优先配额为低置信度 8 条、临界分 6 条、严重错误 4 条、随机 2 条；不足时从剩余候选补齐。
- 同一 `evaluation_result_id` 首版只进入一个校准批次。
- 人工复核结果独立保存，不修改或删除原始 `EvaluationResult`。
- 不认同时必须提交正确结论、主要分歧维度和不超过 1000 字的人工依据。
- 不认同案例自动加入回归集合；本期不执行跨版本回归。
- 所有对话在接口返回前脱敏。
- 准备批次、查询详情和提交复核均不得调用模型 Provider。
- 页面和接口使用中文易懂文案；说明文件固定在 `docs/产品设计` 和 `docs/实施计划`。
