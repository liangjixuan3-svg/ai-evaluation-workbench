# GitHub 演示站实施计划

目标：让面试官通过 GitHub Pages 打开可交互的作品演示站；原有本地 FastAPI 模式不变。

## 交付顺序

1. 演示启动层：Vite 演示构建路径、HashRouter、MSW Worker、显眼的演示模式提示和重置入口。
2. 质量闭环：预置工作台、问题归因、QA 审核、发布复测和评测结果；操作只修改浏览器内模拟状态，不调用真实模型。
3. 规则与采集：预置公司标准、Prompt、导入批次和校准样本。需要真实后端的动作要明确标为模拟或禁用，不能假装完成真实处理。
4. 发布链路：GitHub Actions 测试并构建演示站，Pages 发布；仓库名用于 Vite base 路径。
5. 验收：单测、构建、首页及核心页面交互、链接刷新、窄屏、静态产物密钥扫描。

## 约束

- 演示模式不得请求真实 `/api`、DeepSeek 或用户数据。
- 不提交 `.env`、模型密钥、数据库文件、虚拟环境或依赖目录。
- 真实模式继续使用 BrowserRouter 和现有 API，不修改后端业务逻辑。
- 项目尚未配置 GitHub remote，实际推送及 Pages 设置需在仓库确定后进行。
