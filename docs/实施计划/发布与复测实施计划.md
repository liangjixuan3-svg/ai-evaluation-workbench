# 发布与复测实施计划

> **执行要求：** 按测试先行逐项实现，完成一项后运行目标测试，再进入下一项。

**目标：** 实现 QA 发布登记、严格双样本复测、结果对比、问题关闭和可完整体验的演示数据。

**架构：** 复用现有 `RetestRun`、`RetestSample` 与评测 Provider。后端增加工作台查询和执行服务，前端增加独立发布与复测页面；演示脚本补齐完整数据关系，不引入新基础设施。

**技术栈：** FastAPI、SQLAlchemy、MySQL/SQLite、React、TypeScript、Vitest。

## 全局约束

- 真实业务必须同时满足历史回放与新增样本两组最低数量。
- 复测锁定原评测规则、Prompt、模型和阈值，保证前后可比较。
- 页面中文易懂，沿用现有视觉规范并兼容移动端。
- 单人维护、单台服务器、每日处理量少于一万条。
